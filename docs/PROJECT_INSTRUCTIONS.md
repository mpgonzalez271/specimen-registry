# SAR — Project Instructions (Workspace Copy)

**These instructions are permanent, non-negotiable, and shared across every session that touches SAR.**

## Standing Hard Rules

### Rule 1 — No contact with Ship recipients as part of SAR

The four Ship recipients from the 2026-07 CHEE sprint incident:
- Frido Welker (University of Copenhagen paleoproteomics)
- Fabrice Demeter (Copenhagen / MNHN Paris — Cobra Cave PI)
- Maria Kopsacheili (ICE-CSIC Barcelona — SN 2023vjh)
- Jörn Peckmann (Universität Hamburg — carbonate biomarkers)

Do NOT:
- Email them about SAR
- Send them SAR memos, drafts, previews, or launch announcements
- Ask them to advise, review, contribute, or endorse SAR
- Contact them via LinkedIn, ORCID messaging, conference chairs, or any other channel about SAR
- Route SAR outreach through their collaborators

DO:
- Cite their published papers in SAR where relevant (this is normal academic infrastructure use)
- Ingest specimens they've published on (Denisova 8 ZooMS, etc.) — the papers are public record
- Accept if they encounter SAR organically and cite/use it in year 2+ (that's the whole point)

**This rule is permanent, not "until things cool down."** The SAR audience is the field, not four specific people.

### Rule 2 — Source-lock all data

Every specimen record and analysis record in SAR must be traceable to:
- A specific DOI
- A quoted passage from the paper
- A page number where available

No claim from memory. No AI-generated content in the database. No unverified secondary citations. This is the same discipline the CHEE sprint identified as required.

### Rule 3 — No memos, no hail-mary framings, no specialist outreach as an SAR channel

SAR is infrastructure. It ships tools. It does not ship hypotheses.

If SAR-related work produces an interesting scientific observation, that goes into a Path C preprint under Michael's name on OSF/MetaArXiv — NOT into a memo to a specialist.

### Rule 4 — AI-assistance disclosure

- Every SAR-produced artifact (website "About" page, README, technical write-up, preprint) discloses AI assistance where used.
- Discovery / ingest LLM assistance is disclosed.
- Human review (Michael's) is documented per publication.

### Rule 5 — Separation from FQHC 340B Compliance

- Separate domain (`specimenregistry.org` recommended).
- Separate GitHub org (`specimen-registry` recommended).
- Separate identity — SAR must be handoffable to a nonprofit or foundation someday without any entanglement with FQHC 340B Compliance business operations.
- Michael's authorship / maintainership is fine; but the entity SAR is is not FQHC.

## What requires confirm_action

The following SAR actions are A-tier and require Michael's explicit `confirm_action` approval before execution:

- Domain purchase (financial + external commitment)
- GitHub org creation (external commitment, published identity)
- Any public post about SAR (Bluesky, Reddit, X, LinkedIn, personal blog, etc.)
- Any email to any specialist about SAR
- Any preprint submission
- Any grant application
- Any move to expand SAR beyond a single pilot site

## What does NOT require confirm_action

- Workspace file edits (spec, manifest, notes)
- Reading publisher landing pages / DOI resolution
- Search queries for corpus building
- Draft copy that stays in workspace
- Local dev / scaffolding that doesn't hit external services

## Path C (structured preprint reviews) — supplemental only

- Blocked until SAR v0 is at least alpha-live.
- One preprint per quarter maximum, on OSF or MetaArXiv only.
- Topics MUST NOT overlap with any of the four Ship recipients' active work:
  - No Denisovan population assignments
  - No pre-CAI type Ia supernova progenitors
  - No Toarcian OAE biomarkers
  - No LB6 δ¹⁵N enamel isotopes
- Fully authored by Michael, disclosed as AI-assisted.
- No pre-publication contact with any specialist for review.
- Not to be treated as "SAR marketing."

## Escalation

If SAR encounters a situation not covered by these rules (e.g. a Ship recipient reaches out to Michael independently and mentions SAR), STOP and surface to Michael before any response. Default action: no response until Michael reviews.
